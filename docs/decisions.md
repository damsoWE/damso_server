"답변 완료" 태그는 답변을 보냈다는 뜻이며 문의 종료가 아님. 백엔드 종료 API는 유지하되 앱에서 호출하지 않음, 서버 검증(닫힌 스레드 거부·담당 교사 검증)은 유지. **영향 범위**: `stage=ANSWERED`는 종료 API로만 생기므로 앱에서는 더 이상 생기지 않음 → 학부모 타임라인은 답변 뒤에도 "교사 확인"에서 멈추고, 관리자 화면의 답변 완료 건수는 항상 0. `openapi.yaml`의 `InquiryStage`·`/close`·`THREAD_CLOSED`, F2·F3 spec FR-021, `InquiryStage.java` 주석은 아직 "답변 완료"를 마지막 단계로 설명함 → api 0.7.0에서 `openapi.yaml`에 반영(F2·F3 spec FR-021과 `InquiryStage.java` 주석은 그대로). **미결 → 2026-10-28 해결**(specs/004 US6·US7): ① 문의 목록 응답에 답변 여부가 없어 프론트 FR-002b "답변한 문의는 스레드로"를 무엇으로 판단할지 정하지 않음 → **2026-10-28 해결**: 목록 응답(`ParentInquirySummary`·`TeacherInquirySummary`)에 `hasAnswer`·`lastAnsweredAt` 추가(api 0.7.0), 앱은 `stage`가 아니라 `hasAnswer`로 판단 ② 교사 토큰으로 `/close`를 직접 호출하거나 예전 빌드 앱이 호출하면 스레드가 되돌릴 수 없게 닫히고 이후 재문의·답변이 `409 THREAD_CLOSED`를 받는데 앱에 처리 화면이 없음 → **2026-10-28 해결**: 서버에서 종료 경로를 설정(`damso.inquiry.close-enabled`, 기본 false)으로 막음, 교사 호출 404, 종료 전이·검증 코드와 테스트는 유지. 운영 DB의 닫힌 스레드 0건 확인 | 학부모가 같은 문의에 계속 이어서 물을 수 있도록 (프론트 결정, 팀 합의) |
| 2026-10-28 | [보안·운영] 기획서에 없음 → **CVE-2026-91403(Java JSSE, CVSS 9.1) 대응**: 탈취된 eMudhra 중간 CA 인증서를 JDK가 신뢰해 외부 TLS 호출(OpenAI·FCM·SMTP)이 중간자 공격에 노출될 수 있는 취약점. 공개(2026-10-21) 후 7일 안에 운영 영향 확인 — 운영 JDK Temurin 21.0.12.1로 영향 범위(21 계열 21.0.13 이하)임을 확인했고, 공식 패치 이미지가 아직 없어 ① 매일 베이스 이미지 JDK 버전을 확인해 패치가 나오면 재배포 이슈를 자동 생성하는 감시(`.github/workflows/jdk-patch-watch.yml`) ② 배포 때 베이스 이미지를 항상 새로 받도록 `deploy.yml`에 `pull: true`를 추가함(이슈 #23). 패치 이미지가 나오면 재배포하고 서버 `java -version`으로 확인한 날짜를 이 행에 덧붙인다 | 외부 AI·푸시·메일 호출에 학부모 문의(가명화본)·인증 정보가 오가므로 TLS 신뢰 체계 취약점은 원칙 II·VI(가명화 게이트웨이, 민감정보 비노출)를 우회할 수 있음. 패치 공개와 동시에 반영되게 해 노출 기간을 줄임 |
