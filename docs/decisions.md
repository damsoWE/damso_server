# 기획서 대비 변경 로그

기획서(`docs/아기하마_개발기획서.pdf`)와 달라지는 결정을 기록한다. 기획서 재제출과 발표 Q&A 근거로 쓴다.
불변 보안 원칙(constitution)은 이 로그로 바꾸지 않는다.

| 날짜 | 기획서 원래 내용 → 변경 내용 | 이유 |
|------|------------------------------|------|
| 2026-10-15 | [IA] 가입 시 역할(학부모/교사) 선택 → 초대 코드가 역할을 결정, 선택 단계 없음 | 공개 가입 경로를 없애고 코드로만 가입하게 해 역할 위장 가입을 막음 |
| 2026-10-15 | [IA] 학교 검색·학생/교사 이름 입력 → 초대 코드가 학급·학생을 결정, 입력 단계 없음 | 코드 발행 시 학급·학생이 지정되므로 중복 입력 불필요, 잘못된 연결 방지 |
| 2026-10-15 | [IA] 교사 마이페이지 > 학급 관리 > 코드 재발급 → 코드 발행·재발행은 슈퍼 관리자 전담 | 코드 발행 주체를 한 곳으로 모아 통제, 재발행 시 이전 코드 즉시 무효 |
| 2026-10-15 | [기획] 학교 관리자(문의 건수·처리 상태 열람) → 슈퍼 관리자와 같은 역할로 통합, 코드 발행·학급/학생 명단 관리 추가. 민원 내용 열람 권한 없음은 유지 | 대회용 MVP 범위에서 관리 역할을 하나로 단순화 |
| 2026-10-15 | [기획] 되묻기(요청사항 불명확 시 학부모에게 보완 질문) → MVP 제외 | IA에 화면이 없고 상태·화면 추가로 10/30 일정 부담. AI 생성 문장을 학부모에게 직접 보내게 되어 원칙 V(시스템 안내는 고정 문구만)와도 충돌 |
| 2026-10-15 | [기획] 답변 점검 시 관련 규정 첨부 제안 → MVP 제외, 점검은 "근거 누락" 지적까지만 | 규정 데이터 출처가 없음 |
| 2026-10-15 | [IA] 학부모 "전송 예약 / 예약 목록" → 기획서 "응답 가능 시간(알림 지연)"으로 통합, 학부모가 발송 시각을 고르는 예약 없음 | 같은 목적의 기능이 두 개로 나뉘지 않게 정리, 예약 큐·시간대 처리 부담 제거 |
