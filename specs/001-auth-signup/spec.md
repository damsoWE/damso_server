# Feature Specification: 인증·회원가입·학급 연결 (F1)

**Feature Branch**: `features/f1-auth-signup` (이슈 #2)

**Created**: 2026-10-18

**Status**: Draft

**Input**: User description: "features F1" — `docs/features.md`의 F1 섹션(인증·회원가입·학급 연결). 학부모는 자기 자녀의 담임에게만, 교사는 담당 학급에만 닿도록 초대 코드 기반으로 가입하고 학급·학생에 연결한다. 이후 모든 기능의 권한 판단이 이 연결에서 나온다.

> 이 spec의 사용자는 **슈퍼 관리자**(= 기획서의 "학교 관리자", 코드 발행·명단 관리 전담, 민원 내용 열람 권한 없음), **교사**, **학부모** 세 역할이다.

## Clarifications

### Session 2026-10-18

- Q: 비밀번호 재설정 세부값을 디자인 제안값으로 확정할까요? → A: 확정. 재설정 코드 10분 유효 · 5회 실패 시 10분 잠금 · 비밀번호 영문+숫자 8자 이상 · 재설정 시 모든 기기 로그아웃.
- Q: 탈퇴 후에도 계정의 학생·학급 연결 이력을 개인정보 없이 남길까요? → A: 남긴다. 탈퇴 사실과 연결·해제 이력(계정 UUID, 학생·학급 UUID, 연결·해제 시각)을 append-only로 보존하고, 이메일·이름은 남기지 않는다.
- Q: 로그인 실패 제한을 어떤 방식으로 할까요? → A: 계정(이메일) 기준으로 세되, 10분 잠금 대신 실패할수록 대기 시간을 늘린다.
- Q: 한 계정이 여러 기기에서 동시에 로그인할 수 있게 할까요? → A: 허용한다. 기기마다 세션이 따로 있고, 로그아웃은 그 기기만 끊는다.
- Q: 앱을 쓰지 않아도 로그인 상태를 얼마나 유지할까요? → A: 마지막 사용 후 14일. 앱을 쓸 때마다(세션 갱신 시) 기간이 다시 시작된다.

### Session 2026-10-25

프론트 요청(이슈 #11): 가입 화면은 초대 코드를 먼저 확인하고, 그 결과로 교사용·학부모용 계정 만들기 화면이 나뉜다.

- Q: 가입 전에 코드만 먼저 확인하는 기능을 둘까요? → A: 둔다. 코드가 정하는 역할(교사·학부모)만 알려 주고 학급·학생 같은 연결 대상은 알려 주지 않으며, 코드를 소모하지 않는다. 가입은 지금처럼 코드를 다시 검증한다.
- Q: 코드 확인 단계에는 아직 이메일이 없는데 실패 횟수를 무엇으로 셀까요? → A: 코드 확인 때 가입하려는 이메일도 함께 받아, 가입 단계와 같은 이메일 기준 횟수로 센다(확인·가입 실패가 합쳐져 5회 실패 시 10분 잠금). IP 기준은 FR-011 결정대로 쓰지 않는다.
- Q: 이메일·비밀번호 없이 코드 유효 여부를 확인할 수 있게 되어도 괜찮을까요? → A: 괜찮다. 지금도 가입 1단계에 아무 값이나 넣으면 코드 유효 여부가 드러나므로 새로 생기는 노출이 아니다. 실패 사유를 구분하지 않는 응답(FR-010), 이메일 기준 시도 제한(FR-011), 코드의 경우의 수(31종 문자 10자리)와 24시간 만료로 막는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 슈퍼 관리자가 학급과 학생 명단을 만들고 초대 코드를 발행한다 (Priority: P1)

슈퍼 관리자가 앱의 관리자 화면에 로그인해 학급을 만들고 학생 이름을 등록한다. 그 학급을 지정해 교사 초대 코드를 발행하고, 학생 1명마다 학부모 초대 코드를 1개씩 발행한다. 코드 원문은 발행 직후 한 번만 보이고, 학교가 오프라인으로 교사·학부모에게 전달한다. 슈퍼 관리자는 발행 현황(사용됨·미사용·만료·무효)을 보고, 요청을 받으면 코드를 재발행한다. 재발행하면 이전 코드는 즉시 무효가 된다.

**Why this priority**: 공개 가입 경로가 없으므로 코드가 없으면 아무도 가입할 수 없다. 모든 연결의 출발점이다.

**Independent Test**: 서버에서 직접 만든 슈퍼 관리자 계정으로 로그인해 학급·학생 등록, 교사·학부모 코드 발행, 재발행, 발행 현황 조회를 수행하고, 코드 원문이 다시 조회되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 슈퍼 관리자가 로그인한 상태, **When** 학급을 만들고 학생 이름을 등록, **Then** 학급과 학생 명단이 저장되고 목록에서 보인다.
2. **Given** 담임이 없는 학급, **When** 그 학급을 지정해 교사 초대 코드를 발행, **Then** 영문 대문자+숫자 10자리 코드가 발행 응답에서 한 번만 보이고, 이후 발행 현황에서는 원문이 보이지 않는다.
3. **Given** 등록된 학생, **When** 학부모 초대 코드를 발행, **Then** 그 학생 1명에 대한 코드가 1개 발행된다.
4. **Given** 아직 사용되지 않은 코드, **When** 같은 대상으로 재발행, **Then** 새 코드가 발행되고 이전 코드는 즉시 무효가 된다.
5. **Given** 슈퍼 관리자, **When** 발행 현황을 조회, **Then** 코드별 대상(학급·학생), 상태(미사용·사용됨·만료·무효), 발행·만료 시각을 볼 수 있다.
6. **Given** 교사·학부모 계정, **When** 슈퍼 관리자 전용 기능을 호출, **Then** 거부된다.

### User Story 2 - 교사가 초대 코드로 가입해 담임으로 확정된다 (Priority: P1)

교사가 받은 초대 코드와 이름·이메일·비밀번호·약관 동의를 입력하고, 이메일로 받은 6자리 인증 코드를 앱에 입력해 가입을 마친다. 코드가 역할과 학급을 정하므로 역할 선택·학교 검색은 없다. 가입이 끝나면 지정된 학급의 담임으로 확정된다.

**Why this priority**: 교사가 연결되어야 학부모 문의가 닿을 곳이 생긴다.

**Independent Test**: 발행된 교사 코드로 가입·이메일 인증을 마치고, 그 교사가 지정 학급의 담임으로 조회되는지와 코드가 다시 쓰이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효한 교사 초대 코드, **When** 이름·이메일·비밀번호·약관 동의를 입력하고 이메일 인증 코드를 맞게 입력, **Then** 교사 계정이 만들어지고 지정 학급의 담임으로 확정되며 코드는 사용됨이 된다.
2. **Given** 없는·만료된·사용된·무효인 코드, **When** 가입 시도, **Then** 네 경우 모두 같은 응답("코드를 확인해 주세요")을 받아 어떤 경우인지 구분할 수 없다.
3. **Given** 같은 이메일로 코드 입력을 5회 연속 실패, **When** 6번째 시도, **Then** 10분 동안 코드 입력이 잠긴다.
4. **Given** 이미 가입된 이메일, **When** 그 이메일로 가입 시도, **Then** 가입되지 않는다.
5. **Given** 이메일 인증을 마치지 않은 가입 시도, **When** 인증 없이 진행, **Then** 계정이 확정되지 않고 코드도 소모되지 않는다.
6. **Given** 유효한 교사 초대 코드, **When** 가입 전에 코드와 이메일로 코드 확인을 요청, **Then** 역할(교사)만 알려 주고 학급은 알려 주지 않으며, 코드는 소모되지 않아 이어서 가입할 수 있다.
7. **Given** 같은 이메일로 코드 확인과 가입 1단계에서 합쳐 5회 연속 코드 실패, **When** 6번째 확인 또는 가입 시도, **Then** 10분 동안 코드 입력이 잠긴다.

### User Story 3 - 학부모가 초대 코드로 가입해 자녀의 보호자로 확정된다 (Priority: P1)

학부모가 학교에서 받은 초대 코드와 이름·이메일·비밀번호·약관 동의로 가입하고 이메일 인증을 마친다. 가입이 끝나면 해당 학생의 보호자로 확정되고, 홈에서 담임의 공개 프로필을 볼 수 있다. 둘째 자녀부터는 이미 가입한 계정의 마이페이지 > 연결된 학급에서 그 자녀의 코드를 추가로 입력해 연결한다.

**Why this priority**: 학부모–학생–학급 연결이 F2 이후 모든 문의 권한의 기준이다.

**Independent Test**: 학부모 코드로 가입한 뒤 학생 연결을 확인하고, 두 번째 자녀 코드를 추가 입력해 자녀 2명이 연결되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효한 학부모 초대 코드, **When** 가입 정보를 입력하고 이메일 인증을 마침, **Then** 학부모 계정이 만들어지고 해당 학생의 보호자로 확정된다.
2. **Given** 가입한 학부모, **When** 다른 자녀의 학부모 코드를 마이페이지에서 입력, **Then** 그 자녀도 연결되어 연결된 학급 목록에 함께 보인다.
3. **Given** 이미 보호자가 연결된 학생, **When** 다른 학부모가 그 학생의 코드로 연결 시도, **Then** 연결되지 않는다(학생 1명당 보호자 1명).
4. **Given** 교사 계정, **When** 학부모 초대 코드를 입력, **Then** 연결되지 않는다.
5. **Given** 가입한 학부모, **When** 로그인한 계정으로 코드 입력을 5회 연속 실패, **Then** 10분 동안 코드 입력이 잠긴다.
6. **Given** 유효한 학부모 초대 코드, **When** 가입 전에 코드 확인을 요청, **Then** 역할(학부모)만 알려 주고 학생은 알려 주지 않는다.

### User Story 4 - 사용자가 로그인하고 세션을 안전하게 유지한다 (Priority: P1)

가입한 사용자가 이메일과 비밀번호로 로그인하면 저장된 역할(슈퍼 관리자·교사·학부모)의 화면으로 바로 들어간다. 앱을 다시 열면 로그인 상태가 이어지고, 세션이 갱신될 때마다 갱신 수단이 바뀐다. 이미 쓴 갱신 수단이 다시 쓰이면 탈취로 보고 그 세션 계열 전체를 끊는다. 사용자는 로그아웃할 수 있다.

**Why this priority**: 모든 보호된 기능의 전제다.

**Independent Test**: 로그인 → 역할 확인 → 세션 갱신 → 이전 갱신 수단 재사용 → 세션 전체 폐기를 순서대로 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입을 마친 사용자, **When** 맞는 이메일·비밀번호로 로그인, **Then** 로그인되고 응답에서 자신의 역할을 알 수 있다.
2. **Given** 틀린 비밀번호 또는 없는 이메일, **When** 로그인 시도, **Then** 두 경우 모두 같은 응답을 받는다.
3. **Given** 같은 계정으로 로그인을 3회 연속 실패, **When** 30초 안에 다시 시도, **Then** 맞는 비밀번호여도 거부되고 남은 대기 시간이 안내된다. 30초가 지나면 다시 시도할 수 있다.
4. **Given** 연속 실패가 7회 이상, **When** 다시 실패, **Then** 다음 시도까지 대기 시간은 10분을 넘지 않는다.
5. **Given** 연속 실패 기록이 있는 계정, **When** 대기 후 로그인에 성공, **Then** 실패 횟수가 초기화된다.
6. **Given** 로그인된 세션, **When** 세션을 갱신, **Then** 새 갱신 수단이 발급되고 이전 갱신 수단은 쓸 수 없게 된다.
7. **Given** 이미 사용된 갱신 수단, **When** 다시 사용, **Then** 거부되고 그 세션 계열 전체가 폐기되어 다시 로그인해야 한다.
8. **Given** 두 기기에 로그인된 사용자, **When** 한 기기에서 로그아웃, **Then** 그 기기의 세션으로는 더 이상 보호된 기능을 쓸 수 없고, 다른 기기의 세션은 그대로 쓸 수 있다.
9. **Given** 두 기기에 로그인된 사용자, **When** 한 기기의 갱신 수단 재사용이 탐지됨, **Then** 그 기기의 세션 계열만 폐기된다.
10. **Given** 마지막 세션 갱신 후 14일이 지난 기기, **When** 앱을 열면, **Then** 다시 로그인해야 한다. 14일 안에 열면 로그인 상태가 이어지고 기간이 다시 시작된다.

### User Story 5 - 사용자가 비밀번호를 재설정한다 (Priority: P2)

비밀번호를 잊은 사용자가 가입 이메일을 입력하면 6자리 재설정 코드가 메일로 온다. 앱에서 코드를 입력하고 새 비밀번호를 정한다. 가입되지 않은 이메일을 넣어도 같은 안내가 보인다.

**Why this priority**: 계정을 잃으면 다시 가입할 수 없으므로(코드는 1회용) 필요하지만, 가입·로그인보다 뒤에 와도 MVP 시연은 가능하다.

**Independent Test**: 가입·미가입 이메일로 각각 요청해 같은 안내를 확인하고, 받은 코드로 비밀번호를 바꾼 뒤 새 비밀번호로만 로그인되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입된 이메일, **When** 재설정 요청, **Then** "입력한 이메일로 안내를 보냈습니다"류의 안내가 보이고 6자리 코드가 메일로 발송된다.
2. **Given** 가입되지 않은 이메일, **When** 재설정 요청, **Then** 1과 같은 안내가 보이고 메일은 발송되지 않는다.
3. **Given** 유효한 재설정 코드, **When** 코드와 정책에 맞는 새 비밀번호를 입력, **Then** 비밀번호가 바뀌고 해당 계정의 모든 기존 세션이 끊긴다.
4. **Given** 재설정 코드 입력을 5회 연속 실패, **When** 6번째 시도, **Then** 10분 동안 입력이 잠긴다.
5. **Given** 발송 후 10분이 지난 코드, **When** 입력, **Then** 거부된다.

### User Story 6 - 교사 공개 프로필과 연결 현황 (Priority: P2)

교사는 표시 이름과 소개 문구(최대 60자)로 공개 프로필을 관리하고, 학급 관리에서 학생별 학부모 연결 여부를 본다. 학부모는 홈에서 자녀 담임의 공개 프로필을 본다. 어느 쪽도 상대의 이메일은 볼 수 없다.

**Why this priority**: 학부모가 누구에게 문의하는지 알게 하지만, 문의 기능 자체는 프로필 없이도 동작한다.

**Independent Test**: 교사가 프로필을 수정한 뒤 연결된 학부모 계정에서 보이고, 연결되지 않은 학부모에게는 보이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 교사, **When** 표시 이름과 60자 이하 소개 문구를 저장, **Then** 공개 프로필이 바뀐다.
2. **Given** 교사, **When** 60자를 넘는 소개 문구를 저장, **Then** 거부된다.
3. **Given** 자녀가 연결된 학부모, **When** 홈을 열면, **Then** 자녀 담임의 표시 이름·소개 문구가 보이고 이메일은 보이지 않는다.
4. **Given** 다른 학급의 학부모, **When** 이 교사의 프로필을 조회, **Then** 거부된다.
5. **Given** 교사, **When** 학급 관리에서 연결 현황을 조회, **Then** 학생별 학부모 연결 여부(연결됨·미연결)가 보이고 학부모 이메일은 보이지 않는다.

### User Story 7 - 마이페이지에서 내 정보와 계정을 관리한다 (Priority: P3)

사용자는 마이페이지에서 내 정보(이름 등)와 연결된 학급을 보고, 회원 탈퇴를 할 수 있다.

**Why this priority**: 시연 흐름의 필수는 아니지만 계정 수명 주기를 완결한다.

**Independent Test**: 내 정보를 조회·수정하고, 탈퇴 후 그 계정으로 로그인할 수 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자, **When** 마이페이지를 열면, **Then** 자신의 이름·이메일·역할·연결된 학급(교사는 담당 학급, 학부모는 자녀별)이 보인다.
2. **Given** 로그인한 교사·학부모, **When** 현재 비밀번호를 입력하고 회원 탈퇴를 확정, **Then** 모든 세션이 끊기고 그 계정으로 다시 로그인할 수 없다. 비밀번호가 틀리면 탈퇴되지 않는다.
3. **Given** 탈퇴한 계정이 작성했거나 받은 문의, **When** 탈퇴 후, **Then** 원문·이력은 지워지지 않고 작성자는 "탈퇴한 사용자"로 표시된다(원칙 III).
4. **Given** 탈퇴한 학부모·교사, **When** 탈퇴 후, **Then** 이메일·이름이 비식별 값으로 바뀌고 학생·학급 연결이 해제되어, 슈퍼 관리자가 그 학생·학급에 코드를 다시 발행할 수 있다.
5. **Given** 탈퇴한 계정의 이메일, **When** 새 초대 코드로 가입, **Then** 새 계정으로 가입된다.
6. **Given** 슈퍼 관리자, **When** 앱에서 회원 탈퇴를 시도, **Then** 거부된다.
7. **Given** 탈퇴한 학부모, **When** 탈퇴 후 연결 이력을 조회, **Then** 그 계정 UUID가 어느 학생의 보호자였는지와 연결·해제 시각이 남아 있고, 이메일·이름은 없다.

### Edge Cases

- 담임이 이미 있는 학급으로 교사 코드를 발행하려 하면 거부된다(교사–학급 1:1).
- 이미 다른 학급의 담임인 교사가 다른 학급 교사 코드를 입력해도 연결되지 않는다.
- 코드 발행 후 24시간이 지나면 만료되어, 가입 시 없는 코드와 같은 응답을 받는다.
- 이메일 인증 코드를 입력하는 사이 초대 코드가 재발행되면 이전 코드가 무효이므로 가입이 확정되지 않는다.
- 두 사람이 같은 초대 코드로 동시에 가입을 마치면 한 명만 성공한다(1회용).
- 이메일 인증 코드를 다시 요청하면 이전 인증 코드는 무효가 된다.
- 이메일은 대소문자를 구분하지 않고 같은 이메일로 본다.
- 학부모가 연결된 자녀의 학급이 서로 다르면 연결된 학급 목록에 학급별로 따로 보인다.
- 응답 통일: 코드 검증·로그인·비밀번호 재설정 요청은 실패 사유를 응답 내용뿐 아니라 응답 시간 차이로도 드러내지 않도록 한다.
- 코드 입력 잠금 중이나 로그인 대기 중에는 맞는 코드·비밀번호를 넣어도 풀릴 때까지 거부된다.
- 코드 확인과 가입 사이에 코드가 재발행·만료·사용되면 가입 1단계가 없는 코드와 같은 응답을 준다. 앱은 코드 입력 화면으로 돌아간다.

## Requirements *(mandatory)*

### Functional Requirements

**슈퍼 관리자·학급·명단**

- **FR-001**: 시스템은 앱 안에서 슈퍼 관리자 계정을 만드는 경로를 제공하지 MUST NOT 한다. 슈퍼 관리자 계정은 서버 운영자가 직접 만들며, 계정 정보는 코드·설정 파일이 아닌 환경변수로 주입한다. 기본 계정은 없다.
- **FR-002**: 슈퍼 관리자는 학급을 만들고, 학급에 학생 이름을 등록할 수 MUST 있다. 등록된 명단은 이후 F3 가명화의 1차 사전으로 쓰인다.
- **FR-003**: 슈퍼 관리자 기능은 슈퍼 관리자 역할에게만 허용 MUST 한다.
- **FR-004**: 슈퍼 관리자는 문의 원문·정제본·답변에 접근할 수 MUST NOT 있다.

**초대 코드**

- **FR-005**: 슈퍼 관리자는 학급을 지정한 교사 초대 코드와, 학생 1명당 1개의 학부모 초대 코드를 발행할 수 MUST 있다.
- **FR-006**: 초대 코드는 영문 대문자+숫자 10자리이며 헷갈리는 문자(0, O, 1, I, L)를 쓰지 않는다. 예측할 수 없게 생성해야 MUST 한다.
- **FR-007**: 코드 원문은 발행 응답에서 한 번만 보여 주고, 시스템은 원문을 저장하지 MUST NOT 한다(검증용 해시만 저장).
- **FR-008**: 코드는 1회용이며 발행 후 24시간이 지나면 만료된다.
- **FR-009**: 같은 대상(학급의 교사 자리, 또는 학생)으로 재발행하면 이전 미사용 코드는 즉시 무효가 된다. 사용자 스스로 재발행하는 경로는 없다.
- **FR-010**: 코드 검증 실패는 없음·만료·사용됨·무효·대상 불일치(역할이 다른 코드 등)를 구분하지 않고 같은 응답을 반환 MUST 한다.
- **FR-011**: 코드 입력은 5회 연속 실패 시 10분간 잠긴다. 횟수는 계정 기준으로 세고, 계정이 아직 없는 가입 단계에서는 가입하려는 이메일 기준으로 센다.
- **FR-011a**: 시스템은 가입 전에 초대 코드만 확인하는 공개 기능을 제공 MUST 한다. 코드와 가입하려는 이메일을 받아, 쓸 수 있는 코드면 코드가 정하는 역할(교사·학부모)만 알려 주고 학급·학생 등 연결 대상은 알려 주지 MUST NOT 한다. 코드를 소모하지 않으며, 실패 응답(FR-010)과 실패 횟수(FR-011, 같은 이메일 기준으로 가입 단계와 합산)는 가입 1단계와 같다.
- **FR-012**: 슈퍼 관리자는 발행 현황(대상, 상태, 발행·만료 시각)을 조회할 수 MUST 있다. 현황에 코드 원문은 없다.

**가입·이메일 인증**

- **FR-013**: 유효한 초대 코드 없이는 가입할 수 MUST NOT 있다. 공개 가입 경로는 없다.
- **FR-014**: 가입 정보는 초대 코드·이름·이메일·비밀번호·약관 동의뿐이다. 전화번호·주소 등 연락처를 받지 MUST NOT 한다.
- **FR-015**: 역할과 연결 대상(학급 또는 학생)은 코드로만 정해진다. 요청에 담긴 역할·학급·학생 값을 연결 판단에 쓰지 MUST NOT 한다.
- **FR-016**: 가입은 이메일로 발송한 6자리 인증 코드를 맞게 입력해야 확정된다. 확정 전에는 계정이 활성화되지 않고 초대 코드도 소모되지 않는다.
- **FR-017**: 한 이메일로는 계정 하나만 만들 수 있다.
- **FR-018**: 약관은 동의 여부만 저장한다(약관 버전 관리 없음). 동의하지 않으면 가입할 수 없다.
- **FR-019**: 교사 가입이 확정되면 그 교사는 코드에 지정된 학급의 담임이 된다. 교사와 학급은 1:1이다.
- **FR-020**: 학부모 가입이 확정되면 그 학부모는 코드의 학생의 보호자가 된다. 학생 1명당 보호자는 1명이고, 학부모 1명은 자녀 여럿을 연결할 수 있다.
- **FR-021**: 가입한 학부모는 마이페이지에서 학부모 초대 코드를 추가로 입력해 자녀를 더 연결할 수 MUST 있다. 같은 코드 정책(FR-008~FR-011)을 따른다.

**로그인·세션**

- **FR-022**: 사용자는 이메일과 비밀번호로 로그인하고, 응답으로 자신의 역할을 알 수 있다.
- **FR-023**: 로그인 실패는 없는 이메일과 틀린 비밀번호를 구분하지 않고 같은 응답을 반환 MUST 한다.
- **FR-024**: 로그인 실패는 계정(입력한 이메일) 기준으로 연속 횟수를 센다. 2회까지는 대기 없이 다시 시도할 수 있고, 3회째 실패부터 다음 시도까지 대기 시간을 둔다: 3회 30초 · 4회 1분 · 5회 2분 · 6회 5분 · 7회 이상 10분(상한). 대기 중의 시도는 비밀번호가 맞아도 거부하고 실패 횟수에 더하지 않는다. 로그인에 성공하면 횟수는 초기화된다. 가입되지 않은 이메일에도 같은 대기 규칙을 적용해 가입 여부가 드러나지 않게 한다.
- **FR-025**: 세션은 짧은 수명의 접근 수단과 갱신 수단으로 나눈다. 갱신 수단은 쓸 때마다 새것으로 바뀌고, 이미 쓰인 갱신 수단이 다시 쓰이면 그 세션 계열 전체를 폐기 MUST 한다.
- **FR-025a**: 한 계정은 여러 기기에서 동시에 로그인할 수 있다. 로그인할 때마다 별도의 세션 계열이 생기고, 갱신 수단 재사용이 탐지되면 그 계열만 폐기한다. 비밀번호 재설정과 회원 탈퇴는 그 계정의 모든 세션 계열을 폐기한다.
- **FR-025b**: 세션은 마지막으로 갱신한 뒤 14일 동안 쓰지 않으면 만료되어 다시 로그인해야 한다. 세션을 갱신할 때마다 14일이 다시 시작된다.
- **FR-026**: 사용자는 로그아웃할 수 있다. 로그아웃은 그 기기의 세션 계열만 폐기하고, 다른 기기의 세션은 유지된다.
- **FR-027**: 인증은 요청 헤더로만 하며 쿠키 세션을 쓰지 않는다.

**비밀번호**

- **FR-028**: 비밀번호는 영문과 숫자를 포함한 8자 이상 64자 이하여야 한다. 원문을 저장하지 않고 단방향으로 변환해 저장 MUST 한다.
- **FR-029**: 비밀번호 재설정은 가입 이메일로 6자리 재설정 코드를 보내고, 앱에서 코드와 새 비밀번호를 입력하는 방식이다. 가입 여부와 관계없이 같은 안내를 보여 준다. 같은 이메일의 메일 발송 대기(가입 인증 메일과 공유) 중이면 가입 여부와 관계없이 "잠시 후 다시 시도"와 남은 시간을 알린다 — 대기는 계정 조회 전에 이메일 기준으로 판단하므로 가입 여부가 드러나지 않는다(2026-10-28, 이슈 #22).
- **FR-030**: 재설정 코드는 10분간 유효하고 1회용이며, 5회 연속 실패 시 10분간 잠긴다. 다시 요청하면 이전 코드는 무효가 된다.
- **FR-031**: 비밀번호가 재설정되면 해당 계정의 모든 기존 세션을 폐기한다.
- **FR-032**: 이메일 인증 코드도 10분간 유효하고 1회용이며, 5회 연속 실패 시 10분간 잠긴다.

**프로필·연결 현황·마이페이지**

- **FR-033**: 교사는 공개 프로필(표시 이름, 소개 문구 최대 60자)을 수정할 수 있다. 사진은 없다.
- **FR-034**: 학부모는 연결된 자녀의 담임 공개 프로필만 볼 수 있다.
- **FR-035**: 교사는 담당 학급의 학생별 학부모 연결 여부를 볼 수 있다. 다른 학급의 현황은 볼 수 없다.
- **FR-036**: 어떤 응답에서도 다른 사용자의 이메일·연락처를 노출하지 MUST NOT 한다.
- **FR-037**: 사용자는 마이페이지에서 자신의 이름·이메일·역할·연결된 학급을 조회하고, 이름을 수정할 수 있다. 연결된 학급은 교사는 담당 학급과 학생 현황(FR-035)으로, 학부모는 자녀별 학급과 담임 프로필(FR-034)로 보인다.
- **FR-038**: 교사·학부모는 현재 비밀번호를 다시 입력해 회원 탈퇴할 수 있다. 슈퍼 관리자는 앱에서 탈퇴할 수 없다(서버에서 관리, FR-001). 탈퇴하면 모든 세션이 폐기되고 그 계정으로 다시 로그인할 수 없다. 문의 원문·이력은 삭제하지 않는다(원칙 III). 탈퇴 즉시 계정의 이메일·이름은 비식별 값으로 바뀌고, 이력에는 "탈퇴한 사용자"로 표시된다. 학생·학급 연결은 해제되어 슈퍼 관리자가 그 학생·학급에 코드를 다시 발행할 수 있다. 같은 이메일로는 새 초대 코드로 다시 가입할 수 있다.
- **FR-038a**: 시스템은 보호자 연결과 담임 연결이 생기고 해제된 이력, 그리고 탈퇴 사실을 계정 UUID·학생 또는 학급 UUID·시각으로 append-only 기록 MUST 한다. 이 이력에는 이메일·이름 등 개인정보를 남기지 MUST NOT 하고, 수정·삭제 경로를 두지 않는다(원칙 III·VI).

**공통 보안**

- **FR-039**: 외부에 보이는 학급·학생·사용자·코드 식별자는 UUID다.
- **FR-040**: 모든 조회·변경은 인증 주체와 저장된 연결(학급·학생)을 기준으로 건별 권한을 검증 MUST 한다.
- **FR-041**: 초대 코드 원문, 인증·재설정 코드, 비밀번호, 갱신 수단을 로그에 남기지 MUST NOT 한다.

### Key Entities *(include if feature involves data)*

- **사용자(계정)**: 이메일(로그인 식별, 고유), 비밀번호(단방향 변환값), 이름, 역할(슈퍼 관리자·교사·학부모), 약관 동의 여부, 상태(인증 대기·활성·탈퇴). 연락처는 없다.
- **학급**: 슈퍼 관리자가 만든 반. 담임 교사 0~1명과 연결된다.
- **학생**: 학급에 속한 학생 이름. 보호자 0~1명과 연결된다. F3 가명화 사전의 원천.
- **초대 코드**: 종류(교사·학부모), 대상(학급 또는 학생), 해시, 상태(미사용·사용됨·만료·무효), 발행·만료·사용 시각. 원문 없음.
- **교사 공개 프로필**: 교사 1명당 1개. 표시 이름, 소개 문구(60자 이하).
- **보호자 연결**: 학부모–학생 관계. 학부모 1 : 학생 N, 학생 1 : 학부모 1.
- **연결 이력**: 보호자·담임 연결이 생기고 해제된 기록과 탈퇴 사실. 계정 UUID, 학생 또는 학급 UUID, 종류(연결·해제·탈퇴), 시각. append-only이고 개인정보는 없다.
- **이메일 확인 코드**: 용도(가입 인증·비밀번호 재설정), 대상 이메일, 해시, 만료 시각, 실패 횟수.
- **세션(갱신 수단 계열)**: 로그인 1회(기기 1대)마다 생기는 세션. 사용자 1 : 세션 N. 회전 이력과 폐기 여부를 가진다.
- **실패 횟수·잠금**: 대상(계정 또는 이메일)과 종류(로그인·코드 입력·인증 코드·재설정 코드)별 연속 실패 횟수와 다음 시도 가능 시각(코드 입력은 잠금 해제 시각, 로그인은 대기 종료 시각).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 초대 코드를 받은 교사·학부모가 메일 수신 시간을 빼고 3분 안에 가입·이메일 인증·연결을 마칠 수 있다.
- **SC-002**: 유효한 초대 코드 없이 계정을 만드는 경로가 0개다.
- **SC-003**: 없는·만료·사용된·무효 코드에 대한 응답이 내용상 100% 동일하다. 로그인 실패(없는 이메일·틀린 비밀번호)와 재설정 요청(가입·미가입)도 마찬가지다.
- **SC-004**: 코드 입력(초대·인증·재설정)의 6번째 연속 실패 시도는 100% 잠금으로 거부되고 10분 후 다시 시도할 수 있다. 로그인은 연속 실패 횟수별 대기 시간(FR-024) 안의 시도가 100% 거부되고, 대기 시간은 10분을 넘지 않는다.
- **SC-005**: 학부모·교사가 연결되지 않은 학급·학생·프로필에 접근하는 시도는 100% 거부된다.
- **SC-006**: 어떤 응답·로그에서도 다른 사용자의 이메일, 코드 원문, 비밀번호가 발견되지 않는다.
- **SC-007**: 이미 쓴 갱신 수단을 재사용하면 해당 세션 계열이 즉시 폐기되어, 이후 그 계열의 어떤 수단으로도 접근할 수 없다.
- **SC-008**: 같은 초대 코드로 동시에 가입을 시도하면 정확히 1건만 성공한다.

## Assumptions

- 이메일 인증 코드 세부값(10분 유효, 5회 실패 시 10분 잠금)은 clarify에서 확정한 비밀번호 재설정 코드 값과 같게 맞췄다.
- 이메일 발송 실패 시 사용자는 인증 코드를 다시 요청할 수 있다. 재요청 빈도 제한은 plan에서 정한다.
- 학급 정보는 학년·반 등 최소 식별 정보만 갖는다. 학교는 단일 학교(대회용 1차 MVP)로 본다.
- 학생 명단 수정·삭제, 학급 삭제, 담임 교체는 이 spec 범위 밖이다. 필요하면 별도 결정한다.
- 슈퍼 관리자 화면의 "문의 건수·처리 상태" 조회는 F2·F5에서 다룬다.
- 알림 설정(응답 가능 시간 등)은 공통 알림 결정에 따라 F2·F4에서 다룬다.
- 소셜 로그인·사진 업로드는 MVP 제외다.
- 공통 에러 형식, UUID, 기본 거부 접근 통제, 입력 검증은 `specs/000-foundation`을 따른다.
- IA와 달라지는 점(역할 선택 단계 없음, 학교 검색 없음, 교사 코드 재발급 없음, 슈퍼 관리자 역할 추가)은 `docs/decisions.md` 기록 대상이다.
