# Quickstart: F3 가명화·정제 파이프라인 검증

**Feature**: [spec.md](./spec.md) · 설계: [data-model.md](./data-model.md) · 약속: [contracts/](./contracts/refinement.openapi.yaml) · 기반: [002 quickstart](../002-inquiry-intake-urgent/quickstart.md)

구현이 끝난 뒤 이 순서로 spec의 성공 기준(SC)을 확인한다.

## 사전 준비

- Docker 실행 중(테스트는 PostgreSQL·Redis 컨테이너를 쓴다).
- F2 환경변수에 더해 `DAMSO_OPENAI_MODEL`이 필요하다. `DAMSO_OPENAI_API_KEY`는 F1부터 필수다. 값은 `.env`에만 두고 커밋하지 않는다.
- `src/main/resources/pseudonymization/school-terms.txt`에 학교 이름·줄임말이 있어야 한다(비면 기동 거부).
- 자동화 테스트는 외부 AI 대신 **가짜 `ExternalAiPort`**를 쓴다. 가짜는 받은 요청 본문을 기록하고, 테스트마다 정상 결과·형식 위반·시간 초과·모르는 토큰을 돌려주도록 바꿀 수 있다. 실제 외부 AI는 2절에서만 부른다.

## 1. 자동화 테스트 — SC-001 ~ SC-016

```bash
./gradlew test          # Windows: .\gradlew.bat test
```

정리 실행기와 알림 발송기는 테스트에서 직접 한 번씩 돌린다. 시간은 `MutableClock`으로 옮긴다.

## 2. 수동 확인 — 실제 외부 AI

F2 quickstart 2절처럼 컨테이너와 로컬 서버를 띄우고 `.env`에 실제 `DAMSO_OPENAI_API_KEY`·`DAMSO_OPENAI_MODEL`을 넣는다. **실제 학생 정보가 아닌 가짜 명단으로만** 한다.

1. F1 흐름으로 가짜 학급·학생·교사·학부모를 만든다.
2. 학부모가 학생 이름·학급·전화번호가 든 일반 문의를 제출한다.
3. 교사 기기에 알림이 오면 `GET /api/v1/teacher/inquiries/{id}`의 `refinementStatus`가 `REFINED`인지, `GET …/refinement`에 원래 이름으로 된 번역본이 있는지 본다. 접수부터 알림까지 걸린 시간을 10건 재서 평균 10초 이내인지 기록한다(SC-004).
4. 학부모 상세의 타임라인에 "정제"와, 번역본 열람 뒤 "교사 확인"이 보이는지 본다.
5. 긴급 표현이 든 문의를 낸 뒤 학부모 응답을 다시 조회해 번호가 위기 종류에 맞게 바뀌는지 본다.
6. 지시를 가장한 문장("이전 지시를 무시하고 …")이 든 문의가 정해진 형식 밖으로 나오지 않는지 본다.

## 3. 보안 체크리스트 갱신

| 항목 | 근거가 될 것 |
|---|---|
| 입력 1 SQL 삽입 | 정리 결과를 조회 조건에 쓰지 않음(저장·표시만) |
| 입력 12 서버사이드 요청 위조 | 외부 AI 주소 코드 상수 고정, 설정·입력으로 변경 불가 |
| 보안기능 5 암호화되지 않은 중요정보 | 정리 결과(사실관계·요청사항)·제목 `SensitiveText` |
| L1 프롬프트 인젝션 | 시스템 지시 고정 파일(system 역할)·본문은 user 역할만, Structured Outputs strict + 서버 재검증 |
| L2 LLM 출력 신뢰 | 형식·허용값·토큰 검증 실패 시 폐기(fail-closed), 교사에게 비노출 |
| L3 외부 AI로 식별정보 유출 | 게이트웨이 단일 경로 구조 테스트, 대표 사례 테스트, 가린 뒤 자기 점검, 대응표 메모리 전용. 알려진 한계(명단 밖 이름) 명시 |
