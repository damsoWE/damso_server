# Feature Specification: 일반 문의 위협·폭언 표현 표시

**Feature Branch**: `features/f3-threat-expression-flag` (이슈 #9)

**Created**: 2026-10-26

**Status**: Draft

**Input**: User description: "[Feat] 일반 문의 위협·폭언 표현 규칙 탐지와 교사 화면 표시 (이슈 #9)". 학부모 문의에 교사·학생을 향한 위협이나 폭언이 있으면 교사가 이를 놓치지 않게 한다. 외부 AI 정리(번역본)는 위협·폭언 사실을 문장으로 남기지만 호출마다 편차가 있었다(예시에 없는 표현 12/14, 학생 비하를 잘못 귀속한 사례 포함). 서버의 고정 표현 목록으로 원문을 검사해, 외부 AI 결과와 상관없이 교사 화면에 표시를 붙인다.

> 이 spec의 사용자는 **교사**(담임, 문의 목록·상세 확인)와 **학부모**(문의 작성)다. 문의 접수·긴급 판정은 F2, 번역본·원문 열람은 F3가 만든 것을 그대로 쓰고, 이 기능은 **일반 문의**에 규칙 기반 위협·폭언 표시를 더한다.

## Clarifications

### Session 2026-10-26

- Q: 위협과 폭언을 하나의 표시로 볼지, 두 종류로 나눌지? → A: 하나로 본다. 표시는 "위협·폭언 표현 포함" 하나뿐이다.
- Q: 긴급 판정 표현(자해·폭력)과 겹치는 표현이 든 문의는? → A: 긴급으로만 처리한다. 긴급으로 판정된 문의에는 위협·폭언 표시를 붙이지 않는다(표시는 일반 문의에만).
- Q: 허용할 오탐 수준은? → A: 오탐 최소화. 표현 목록에는 분명한 위협·폭언 표현만 넣고, 판정이 실패하면 표시를 붙이지 않는다. 번역본·원문 열람이 보조 수단으로 남는다.
- Q: (F4 병합 뒤) 같은 스레드에 이어 보내는 재문의도 판정하나? → A: 판정한다. 재문의도 일반 문의라 같은 규칙으로 접수할 때마다 정하고, 교사 상세의 재문의 항목에 표시한다(FR-005c).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 교사가 위협·폭언이 담긴 일반 문의를 목록에서 바로 알아본다 (Priority: P1)

학부모가 교사나 학생을 향한 위협·폭언 표현이 들어간 일반 문의를 보내면, 교사 문의 목록과 상세에 "위협 표현 포함" 같은 표시가 붙는다. 표시는 접수 때 서버가 고정 표현 목록으로 원문을 검사해 정하므로, 외부 AI 정리가 늦거나 실패하거나 위협 사실을 빠뜨려도 똑같이 보인다.

**Why this priority**: 교사가 위협·폭언을 놓치지 않게 하는 것이 이 기능의 존재 이유다. 번역본은 호출마다 위협 사실을 다르게 남겨 그것만으로는 믿을 수 없다.

**Independent Test**: 외부 AI를 끈 상태에서 목록의 위협 표현이 담긴 일반 문의를 접수하고, 교사 목록·상세에 표시가 보이는지 확인한다. 같은 문의를 외부 AI가 켜진 상태에서 다시 접수해 번역본 내용과 상관없이 표시가 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 고정 목록의 위협·폭언 표현이 들어간 일반 문의, **When** 접수, **Then** 교사 목록과 상세에 표시가 붙는다.
2. **Given** 위협·폭언 표현이 없는 일반 문의, **When** 접수, **Then** 표시가 붙지 않는다.
3. **Given** 외부 AI가 중단되어 정리가 끝나지 않았거나 "원문 확인 필요"가 된 문의, **When** 교사가 목록을 열면, **Then** 표시는 정리 상태와 상관없이 접수 때 정해진 대로 보인다.
4. **Given** 번역본이 위협 사실을 빠뜨렸거나 다른 사람에게 잘못 귀속함, **When** 교사가 목록·상세를 열면, **Then** 표시는 번역본 내용과 상관없이 보인다.
5. **Given** 띄어쓰기·줄바꿈만 다른 같은 표현(예: "가만두지 않겠다" / "가만 두지 않겠다"), **When** 접수, **Then** 같은 결과로 판정된다.
6. **Given** 표시가 붙은 문의, **When** 시간이 지나 정리가 끝나거나 교사가 열람·재시도함, **Then** 표시는 바뀌지 않는다.
7. **Given** 다른 학급 교사·다른 학부모·슈퍼 관리자, **When** 표시가 붙은 문의를 조회 시도, **Then** F2·F3와 같이 거부된다.
8. **Given** 긴급 판정 표현과 위협·폭언 표현이 함께 든 문의, **When** 접수, **Then** 긴급으로 처리되고 위협·폭언 표시는 붙지 않는다.
9. **Given** 위협·폭언 판정이 예기치 않게 실패, **When** 접수, **Then** 문의는 정상 접수되고 표시는 붙지 않는다.

### User Story 2 - 정당한 의사 표현은 위협으로 표시하지 않는다 (Priority: P1)

교육청 민원 제기, 면담 요청, 교장·교감 상담 요청처럼 학부모가 쓸 수 있는 정당한 의사 표현은 위협으로 표시하지 않는다. 이를 팀이 정한 대표 사례 모음으로 확인한다.

**Why this priority**: 정당한 민원을 위협으로 낙인찍으면 교사가 학부모를 잘못 대하게 되고 표시 자체를 믿지 않게 된다. 표시가 의미를 가지려면 위협과 정당한 표현을 가르는 기준이 먼저 정해져야 한다.

**Independent Test**: 팀이 정한 "표시하지 않을 대표 사례"(교육청 민원·면담 요청 등)를 모두 접수해 표시가 붙지 않는지, "표시할 대표 사례"를 모두 접수해 표시가 붙는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "교육청에 민원 넣겠습니다" 같은 정당한 의사 표현만 담긴 문의, **When** 접수, **Then** 표시가 붙지 않는다.
2. **Given** "면담을 요청드립니다", "교장 선생님과 상담하고 싶습니다" 같은 문의, **When** 접수, **Then** 표시가 붙지 않는다.
3. **Given** 정당한 의사 표현과 위협 표현이 함께 든 문의, **When** 접수, **Then** 위협 표현 때문에 표시가 붙는다.
4. **Given** 표현 목록이 바뀜, **When** 변경을 반영하려 함, **Then** 대표 사례 모음 전체(표시할 사례·표시하지 않을 사례)가 함께 검증되고, 하나라도 어긋나면 반영하지 않는다.

---

### User Story 3 - 표시는 교사에게만 보이고 학부모에게는 나가지 않는다 (Priority: P1)

위협·폭언 표시는 교사의 판단을 돕는 내부 표시다. 학부모의 문의 목록·상세·접수 응답·알림 어디에도 나가지 않고, 학부모가 자기 문의가 표시됐는지 알 수 있는 경로도 없다.

**Why this priority**: 학부모에게 "위협으로 분류됨"이 보이면 갈등이 커지고, 시스템이 교사 대신 판단을 통보하는 셈이 된다(원칙 V). 표시를 교사 화면에 붙이는 것과 같은 시점에 막혀 있어야 한다.

**Independent Test**: 표시가 붙은 문의를 작성한 학부모 계정으로 접수 응답·목록·상세를 모두 조회해 표시나 그와 관련된 값·문구가 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 표시가 붙은 문의, **When** 학부모가 접수 응답·목록·상세를 보면, **Then** 표시와 관련된 값·문구가 없다.
2. **Given** 표시가 붙은 문의와 붙지 않은 문의, **When** 학부모 응답을 비교, **Then** 응답 형태나 문구에 차이가 없어 표시 여부를 추측할 수 없다.
3. **Given** 교사에게 가는 알림, **When** 표시가 붙은 문의의 알림이 나감, **Then** 알림은 F2·F3의 고정 문구 그대로이고 본문·표현을 담지 않는다.

---

### Edge Cases

- 위협·폭언 표시는 일반 문의에만 붙는다. 긴급 판정 표현(자해·폭력)과 겹치는 표현이 든 문의는 긴급으로 판정되므로 긴급으로만 처리하고 위협·폭언 표시는 붙이지 않는다. 긴급 판정이 언제나 먼저다.
- 학부모가 자기 자신이나 제3자(다른 학부모 등)를 향해 쓴 거친 표현, 이미 일어난 일을 인용한 표현("아이가 '죽여버린다'는 말을 들었대요")은 표현 목록 포함 검사로는 구분하지 못할 수 있다. 어떻게 다룰지는 표현 목록과 대표 사례를 정할 때 함께 정한다.
- 표현을 일부러 비틀어 쓴 경우(초성, 특수문자 끼워 넣기, 다른 글자 섞기)는 규칙으로 다 잡지 못한다. 이 한계는 알려진 것으로 두며, 번역본이 보조 정보로 남는다.
- 표현 목록이 비었거나 읽을 수 없으면 표시 판정이 꺼진 채 서버가 동작하지 않도록 한다(F2 긴급 표현 목록과 같다).
- 표현 목록이 바뀌어도 이미 접수된 문의의 표시는 다시 계산하지 않는다. 표시는 접수 시점의 목록으로 정해진다.
- 표시 판정이 예기치 않게 실패해도 문의 접수와 긴급 판정은 막히지 않는다. 판정이 실패한 문의는 표시를 붙이지 않는다(오탐 최소화). 애매한 표현은 목록에 넣지 않는다.
- 이 기능 이전에 접수된 일반 문의는 표시 판정 대상이 아니다. 운영 배포 전이라 개발 데이터뿐이다.

## Requirements *(mandatory)*

### Functional Requirements

**표현 목록**

- **FR-001**: 위협·폭언 판정에 쓰는 표현 목록은 서버에 고정하고, 변경은 코드 리뷰와 배포를 거쳐서만 한다. 앱(슈퍼 관리자 화면 포함)에서 목록을 편집하는 기능은 두지 않는다.
- **FR-002**: 표현 목록과 대표 사례 모음(표시할 사례·표시하지 않을 사례)은 구현 전에 팀이 정한다. 구현자가 혼자 만든 목록을 구현자의 테스트로만 검증하지 않는다.
- **FR-003**: 대표 사례 모음에는 교육청 민원·면담 요청·교장·교감 상담 요청 같은 정당한 의사 표현이 "표시하지 않을 사례"로 반드시 들어간다. 목록이 바뀌면 대표 사례 전체가 함께 검증된다.
- **FR-004**: 표시는 하나다. 위협과 폭언을 나누지 않고 "위협·폭언 표현 포함" 여부만 정한다.
- **FR-004a**: 표현 목록에는 분명한 위협·폭언 표현만 넣는다(오탐 최소화). 정당한 의사 표현과 겹칠 수 있는 애매한 표현은 넣지 않는다.

**판정**

- **FR-005**: 표시 여부는 일반 문의를 접수할 때 원문을 규칙으로 검사해 정하고 문의와 함께 저장한다. 판정은 외부 AI 호출 이전에, 외부 AI·네트워크 장애와 무관하게 이뤄진다(원칙 IV).
- **FR-005a**: 긴급으로 판정된 문의는 위협·폭언 판정 대상이 아니며 표시를 붙이지 않는다. 긴급 판정이 먼저이고, 위협·폭언 표시는 긴급 판정 결과를 바꾸지 않는다.
- **FR-005b**: 판정이 실패하면 표시를 붙이지 않고 접수는 그대로 진행한다.
- **FR-005c**: 재문의(F4, 같은 스레드에 이어 보내는 문의)도 접수할 때마다 같은 규칙으로 표시를 정한다. 긴급 재문의는 표시하지 않는다. 교사 상세의 재문의 항목에서 보인다.
- **FR-006**: 판정은 띄어쓰기·줄바꿈 같은 표기 차이에 흔들리지 않는다. 같은 표현의 띄어쓰기 변형은 같은 결과를 낸다.
- **FR-007**: 한 번 정해진 표시는 바뀌지 않는다. 정리 완료·원문 확인 필요·교사 열람·재시도·표현 목록 변경 어느 것도 이미 접수된 문의의 표시를 바꾸지 않는다. 표시를 지우거나 고치는 기능은 제공하지 않는다.
- **FR-008**: 표시 판정은 문의 접수를 지연시키거나 막지 않으며, 긴급 판정·외부 AI 정리·교사 알림 규칙을 바꾸지 않는다.
- **FR-009**: 외부 AI의 정리 결과(번역본·정서강도·감정 라벨)는 표시 여부에 영향을 주지 않고, 표시 여부도 정리 처리에 영향을 주지 않는다.

**교사 표시**

- **FR-010**: 담임 교사의 문의 목록과 상세에서 표시가 붙은 일반 문의를 알아볼 수 있다. 표시는 정리 상태(정리 중·정리 완료·원문 확인 필요)와 상관없이 보인다.
- **FR-011**: 표시를 볼 수 있는 사람은 그 문의를 열람할 수 있는 담임 교사뿐이다. 다른 학급 교사·다른 학부모·슈퍼 관리자는 F2·F3의 건별 소유권 규칙대로 거부된다.

**학부모 비노출·로그**

- **FR-012**: 표시와 그 근거는 학부모에게 가는 어떤 응답·안내·알림에도 넣지 않는다. 표시가 붙은 문의와 붙지 않은 문의의 학부모 응답은 형태와 문구가 같다(원칙 V).
- **FR-013**: 판정에 걸린 표현이나 그 위치는 저장하지 않고 로그·오류 응답에도 남기지 않는다. 저장·로그에는 문의 식별자(UUID)와 표시 여부만 남긴다(원칙 VI).
- **FR-014**: 표시는 교사 알림 문구에 넣지 않는다. 알림은 F2·F3의 고정 문구를 그대로 쓴다.

### Key Entities *(include if feature involves data)*

- **위협·폭언 표현 목록**: 서버에 고정된 표현 모음. 코드 리뷰와 배포로만 바뀐다. 팀이 정한다.
- **대표 사례 모음**: 표시해야 할 문장과 표시하지 말아야 할 문장(정당한 의사 표현 포함)의 모음. 표현 목록이 바뀔 때마다 함께 검증하는 기준이다.
- **문의의 위협·폭언 표시**: 일반 문의별로 접수 때 한 번 정해지는 표시. 걸린 표현은 담지 않는다. 교사에게만 보이고 바뀌지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 팀이 정한 "표시할 대표 사례"는 100% 표시되고, "표시하지 않을 대표 사례"(정당한 의사 표현 포함)는 0건 표시된다.
- **SC-002**: 외부 AI가 완전히 중단되어도 표시할 문의의 표시가 100% 교사 목록·상세에 보인다.
- **SC-003**: 같은 문의를 여러 번 접수했을 때 표시 결과가 다른 경우가 0건이다(번역본 편차와 무관).
- **SC-004**: 학부모 응답·안내·알림에 표시나 그 근거가 노출되는 경우가 0건이다.
- **SC-005**: 로그·오류 응답·저장소에서 판정에 걸린 표현이나 그 위치가 발견되는 경우가 0건이다.
- **SC-006**: 표시 판정 때문에 문의 접수가 실패하거나 긴급 판정·교사 알림이 늦어지는 경우가 0건이다.
- **SC-007**: 다른 학급 교사·다른 학부모·슈퍼 관리자가 표시를 볼 수 있는 경우가 0건이다.

## Assumptions

- 로그인·학급 연결은 F1, 문의 접수·긴급 판정·교사 알림은 F2, 번역본·원문 열람·정리 상태는 F3(#6, PR #8)를 그대로 쓴다. 이 기능은 일반 문의에 표시 하나를 더한다.
- 판정 방식은 F2 긴급 판정과 같은 결의 규칙 기반 포함 검사다(외부 AI 미사용). 구체 방식은 plan에서 정한다.
- 판정 대상은 교사·학생·학교 관계자를 향한 위협·폭언이다. 표현 목록이 그 범위를 정하며, 목록 밖의 표현은 표시하지 않는다.
- 표시는 교사의 주의를 끄는 참고 표시일 뿐이고, 문의를 긴급으로 바꾸거나 알림 시점·처리 단계를 바꾸지 않는다.
- 교사 화면에서 어떤 표현이 걸렸는지 강조해 보여 주는 기능은 두지 않는다(걸린 표현을 저장하지 않으므로). 교사는 번역본이나 원문 열람으로 내용을 확인한다.
- 교사가 표시를 해제·이의 제기하는 기능은 이 기능의 범위 밖이다.
- 교사 목록·상세 응답이 바뀌므로 API 명세를 먼저 고치고 새 버전 태그와 프론트 공지를 거친다(contract-first).
- 이 기능 이전에 접수된 일반 문의는 다시 판정하지 않는다. 운영 배포 전이라 개발 데이터뿐이다.
